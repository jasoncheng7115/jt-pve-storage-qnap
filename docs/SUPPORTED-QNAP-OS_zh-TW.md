# 這個外掛支援哪些 QNAP 作業系統

簡短版：**它是針對 QTS 5.1 與 QuTS hero h5.1 撰寫的。** 比 QTS 4.5.1 更舊的版本，會在加入儲存的當下就被拒絕，不會等到之後才發現。

這一頁刻意把「支援」、「應可運作」與「不支援」分清楚，因為其中兩個是承諾，另一個不是。

---

## 一、硬性需求：Storage Manager V2

QNAP 有兩代 Storage Manager，而它們是**兩套不同的 CGI 呼叫**，不是同一套 API 的兩個版本。這個外掛只實作 V2。

韌體自己會回報是哪一種。`authLogin.cgi` 會回傳：

| `<storage_v2>` | `<is_zfs>` | 代表什麼 | 本外掛 |
|---|---|---|---|
| 不存在，或 `0` | — | 舊版 Storage Manager | **拒絕** |
| `1` | `0` | LVM 上的 Storage Manager V2 —— QTS | 支援 |
| `1` | `1` | ZFS —— QuTS hero | 支援，且有即時複製 |

`pvesm add` 在寫入任何東西之前就會做這個檢查，所以太舊的韌體會立刻失敗，訊息裡帶著版本號 —— 而不是加得乾乾淨淨、之後卻列不出任何東西。

安裝任何東西之前，先確認：

```
pve-qnap-api-probe --host <nas> --user admin --insecure
```

## 二、支援對照表

| 作業系統 | 版本 | 狀態 | 說明 |
|---|---|---|---|
| **QTS** | **5.1.x** | **支援** | 這個外掛撰寫時所針對的韌體世代 |
| QTS | 5.2.x | 應可運作 | 同一套 API；未驗證。歡迎回報實際狀況。 |
| QTS | 4.5.1 – 5.0.x | 應可運作 | `storage_v2` 的起始版本；未驗證。 |
| QTS | 4.5.0 以下 | **不支援** | 舊版 Storage Manager。`pvesm add` 會直接拒絕。 |
| **QuTS hero** | **h5.1.x** | **支援** | ZFS。有即時複製，所以 Proxmox VE 的連結複製是瞬間完成的 |
| QuTS hero | h5.2.x | 應可運作 | 未驗證 |
| QuTS hero | h4.5.x – h5.0.x | 應可運作 | 未驗證 |
| QuTScloud | 任何版本 | **不支援** | 雲端映像，沒有這種形式的本機儲存池 |
| QNE Network OS | 任何版本 | **不支援** | 不同的產品線；沒有 Storage Manager |
| TR 系列擴充櫃上的 QTS | — | 不適用 | 擴充櫃不是 NAS |

「應可運作」的意思是：這個外掛用到的部分沒有已知的差異 —— 不代表有人真的跑過。請當成任何未測試的組合來看待。

## 三、QTS 還是 QuTS hero？這會改變「複製」的代價

兩者都支援，外掛在任一種上都能運作。差別在一個操作，而那個差別很大。

這個外掛的每一次複製都是從快照做出來的。在 **QTS** 上那是真的複製：對 200 GB 範本做連結複製會寫入 200 GB，花的時間跟完整複製一樣。在 **QuTS hero** 上是*即時*複製，新的 LUN 與快照共用區塊，所以連結複製是瞬間完成，而且不佔額外空間。

| | QTS（LVM） | QuTS hero（ZFS） |
|---|---|---|
| 快照 | 支援 | 支援 |
| 還原 | 支援 | 支援 |
| 連結複製（`qm clone`） | 可用，但是**真的複製** | 即時 |
| 完整複製 | 複製 | 複製 |
| 大量從範本部署 | 慢 | 快 |

如果正在為 Proxmox VE 叢集選購硬體，而且預期會大量從範本部署，這一點就是決定性的因素。

在 QuTS hero 上有一個後果要知道：即時複製會把來源快照當成自己的後備儲存。因此外掛會在範本上留一個快照；當還有連結複製存在時刪除範本會失敗 —— 而且訊息會明講原因，不是丟一個錯誤代碼。

## 四、機型需求，這和韌體版本是兩回事

一台機器可以跑在支援的韌體上，卻仍然做不到需要的事。

* **iSCSI 目標服務。** 範圍內的每一台 NAS 都有，但出廠是**關閉**的。請到「儲存與快照總管 → iSCSI 與光纖通道」開啟。服務關閉時外掛會拒絕加入儲存，並說明原因。
* **儲存池。** 這個外掛建立的是區塊型 LUN，必須放在儲存池裡。磁碟被設定成靜態磁碟區的 NAS 沒有可用的儲存池。
* **快照。** QNAP 入門機型完全不支援 iSCSI LUN 快照，而且**外掛沒有辦法事先檢查**。加入儲存時它會提出警告，請你先對一顆測試磁碟做一次快照，再開始依賴這個功能。請查閱你的機型規格頁上的「快照」欄位。
* **足夠的 LUN 數量。** 一顆虛擬機磁碟就是一個 LUN。上限因機型而異，外掛會向 NAS 讀取而不是假設；`pve-qnap-api-probe` 會印出來。這是這個儲存真正的上限，而且再多的剩餘空間都改變不了它。

## 五、Proxmox VE

| | 版本 |
|---|---|
| Proxmox VE | 8.0 以上 |
| 儲存外掛 API | 10 – 15，載入時協商 |

API 版本是協商而不是寫死的，因為宣稱高於節點自身的版本會讓 PVE 直接拒絕整個外掛，該節點上所有這個類型的儲存都會消失。

套件必須安裝在**叢集的每一個節點**上。

---

## 六、如果你的組合不在表上

請執行探索工具，並把輸出寄來 —— 它會印出機型、韌體、兩個判別旗標、數量上限與儲存池，而且不會建立任何東西：

```
pve-qnap-api-probe --host <nas> --user admin --insecure --node
```
